# Specs

One file per milestone, numbered in build order. Each has:

- **Goal** — what this milestone delivers or proves, in a sentence or two.
- **Contract** — what has to be observably true when it is done. Outcomes, not implementation.
- **Progress** — a checklist ticked as work lands. This is the live status. Check here before
  asking "what's done"; don't reconstruct it from a past conversation.

Every checklist update comes with a short plain-language note on what happened and why — a silent
checkmark defeats the point of tracking status here.

Start a new spec rather than growing an existing one past its contract. Parked ideas and explicit
non-goals live in `future-considerations.md` — that file is part of the submission, because the
brief judges *what you left out* as much as what you built.

Build order and the reasoning behind it are in `../CLAUDE.md`.
